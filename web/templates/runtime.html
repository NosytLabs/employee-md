RUNTIME

From contract to running agent

The schema is only useful if your agent actually obeys it. The runtime package is a small Python SDK that turns a validated employee.md into a system prompt, a guardrail checker, a scope checker, and a budget tracker. Your executor must apply these checks; generating a prompt alone does not enforce a contract.

system_prompt()

Prompt composition

Compose the contract's mission, scope, guardrails, and budget into plain text. Pass it through your configured model client's supported system-message interface.

is_action_allowed()

Guardrail check

Case-insensitive literal substring matching against guardrails.prohibited_actions in either direction. A nonempty, non-matching action returns True. It does not check lifecycle, scope or permissions. Use canonical action IDs and enforce authorization in the executor.

budget.try_spend()

Spend tracker

Thread-safe budget bound to economy.budget_limit. Raises BudgetExceeded when a spend would push past the configured cap. Limits and spends must be finite, non-negative numbers; booleans and invalid values raise ValueError. None is the only uncapped setting.

Check policy before execution

The runtime ships with the validator. Use the repository-backed install in step 01 of the quickstart. 

from runtime import Employee

emp = Employee.from_file("employee.md")
system_prompt = emp.system_prompt()

action_id = "write_unit_tests"  # use executor-owned identifiers
if not emp.is_active:
    raise PermissionError("The employee is not active")
if not emp.is_in_scope("Write unit tests").in_scope:
    raise PermissionError("The task is outside the declared scope")
if not emp.is_action_allowed(action_id):
    raise PermissionError("The action is explicitly prohibited")
emp.budget.try_spend(0.05)  # can raise BudgetExceeded or ValueError
# Apply tool permissions/sandbox policy before performing any action.
# Generating a system prompt does not replace these checks.

Compose a LangChain prompt

Install the separate LangChain packages and explicitly configure a provider-supported model. This example composes a chain; it does not execute a request or enforce the contract.

import os
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from runtime import Employee

emp = Employee.from_file("employee.md")
prompt = ChatPromptTemplate.from_messages([
    ("system", emp.system_prompt()),
    ("user", "{task}"),
])
model = emp.to_langchain_kwargs()["model"] or os.environ["MODEL_NAME"]
llm = ChatOpenAI(model=model)
chain = prompt | llm
Scope and limitations

The runtime is a thin wrapper, not a sandbox. is_action_allowed is a literal substring check, not a real policy engine. It does not normalize synonyms or separators. is_in_scope has a separate heuristic token matcher. budget uses in-process floating-point accounting and resets when the process restarts; it is not an exact-decimal, persistent or cross-process ledger. Use executor-side authorization, sandboxing and durable accounting where those guarantees are required.
